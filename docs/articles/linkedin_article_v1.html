The Critical Fix: Dynamic --base-href

When Flutter Web is hosted in a subfolder (like /neobrutalist-resume/), Flutter's asset loader must know its root path. Otherwise, the browser requests main.dart.js from root, throwing immediate 404 Not Found crashes. We solved this dynamically in GitHub Actions:

.github/workflows/deploy.yml YAML 
- name: Build Flutter Web Release
  run: flutter build web --release --base-href "/${{ github.event.repository.name }}/"

Because ${{ github.event.repository.name }} dynamically resolves to your repository name, you can name your repository whatever you want, and CI automatically injects the correct URL base path.

📸 FIGURE 7 • ⚡ COLD-START BLANK SCREEN FIX Instant Pure-CSS Pre-Loader & Handshake

⚡ Section 7: Slaying the Flutter Web Cold-Start "Blank Screen"

In Flutter Web, before Dart code can mount its first frame, the browser must fetch flutter.js, canvaskit.wasm (~8 MB), and main.dart.js (~3 MB). Without a pre-loader, users experience a jarring 2–4 second blank beige screen.

❌ DEFAULT FLUTTER WEB (COLD START)

Empty <body> tag. The user stares at a blank screen for 3,000ms while large WebAssembly packages download over the wire. High bounce rates.

✅ INSTANT PURE-CSS PRE-LOADER (< 20ms)

Renders immediately upon HTTP response with zero JS dependencies. Branded with Neobrutalist borders, tilted badge, and electric blue progress runner.

Architecture: The 4-Phase Engine Handshake Protocol

PHASE 1
Instant Paint (<20ms)
HTTP response loads pure-CSS Neobrutalist Splash Card before any JS is evaluated.
PHASE 2
Engine Download (1.5s)
Browser streams canvaskit.wasm (~8MB) & main.dart.js in background.
PHASE 3
DOM Injection
Flutter Web engine bootstraps and injects <flutter-view> into DOM.
PHASE 4
Observer Handshake
MutationObserver detects root view, smoothly triggers 300ms fadeout, and removes splash.
web/index.html • Handshake Protocol JAVASCRIPT 
// 1. Observe when Flutter engine mounts its root view into the DOM
const observer = new MutationObserver(() => {
  const fltView = document.querySelector('flutter-view');
  if (fltView) {
    splash.style.opacity = '0'; // Smooth 300ms fadeout transition
    setTimeout(() => splash.remove(), 300);
    observer.disconnect();
  }
});
observer.observe(document.body, { childList: true, subtree: true });

🚀 Section 8: Fork & Deploy Your Own in 1 Minute

You don't need Flutter installed locally to launch your own resume. The entire build and release lifecycle is automated through GitHub Actions:

1
Fork the Repository
Navigate to github.com/JBavaji/neobrutalist-resume and click Fork to duplicate the repository into your GitHub account.
2
Personalize Your Data
Edit assets/data/resume_data.json directly in the GitHub web editor with your name, experience, skills, and links.
3
Enable GitHub Actions
Go to Settings > Pages in your repository. Under Build and deployment > Source, select GitHub Actions.
4
Push to Main
Commit your changes. GitHub Actions automatically builds and deploys your resume to: https://<username>.github.io/neobrutalist-resume/
